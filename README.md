# You Own It

为 [MyGo Music](https://github.com/egoist/mygo-music) 提供在线音乐服务接入能力的纯插件。
迁移自原 mygo-cloudmusic 的缓存源码，沿用 AGPL-3.0；来源见 [NOTICE.md](NOTICE.md)。

需要 **MyGo Music 0.1.22 或更新版本**。同一插件适用于 macOS、Linux 和 Windows，
不需要 Node、ffmpeg、额外服务或启动程序权限；开发工具仅用于修改插件。

## 安装与登录

在 MyGo Music 的「设置 → 插件 → +」中粘贴：

```text
https://github.com/fansion314/mygo-music-yoi
```

也可使用[一键安装链接](mygo-music://install-plugin?repo=fansion314/mygo-music-yoi)，
或选择 [Release](https://github.com/fansion314/mygo-music-yoi/releases/latest) 中的
`mygo-music-yoi-0.1.1.zip`，
或选择构建生成的干净目录 `dist/mygo-music-yoi/`。不要选择含有 `node_modules` 的开发目录，
宿主安装器会拒绝其中的符号链接。也可在「显示插件文件夹」打开的目录下新建
`world.fansionia.mygo-music-yoi`，放入根目录的 `plugin.json`、`index.js` 和 `locales/`。

启用插件后，点击登录，用对应服务的手机客户端扫码并确认。二维码过期会自动刷新。
歌单、收藏和订阅从账号同步。不会读取旧版客户端的凭据、缓存、队列或配置。

客户端通过 GitHub 最新正式 Release 安装通用 ZIP，并检查后续更新。
插件 ID 保持 `world.fansionia.mygo-music-yoi`，已有安装可更新并保留登录和设置。

## 纯插件的边界

- 当前宿主没有私人 FM「不再推荐」操作入口，插件不会把普通下一首误当成不再推荐。
- 心动模式以插件收到的最近播放的喜欢歌曲为种子，没有时选喜欢列表中的第一首。
  宿主不提供当前队列或电台停止通知；心动上下文保留至切换电台或账号，不能等价复现旧版的当前歌曲入口。
- 用户搜索使用自定义页面，原生搜索没有用户标签；先提交搜索，再打开用户搜索。
- 原生歌手页展示首批专辑。更多专辑和最新歌曲通过扩展页翻页，不静默丢弃其余内容。
- 动态显示文字、转发文字和分享的歌曲／专辑／歌手／歌单；宿主不支持动态图片画廊和视频播放。
- 评论使用宿主的统一列表，回复及地区信息显示为文字，不提供旧版完全相同的布局。
  本插件不额外提供发表评论、专辑收藏、歌单重排等旧版实现未提供的操作。
- 最近播放展示服务端最近播放接口提供的最多 100 首；`played` 钩子只记录本机心动种子，
  不伪造云端听歌记录，也不提供完整历史导出或删除。
- 登录 Cookie 保存在宿主的插件本机存储中，**不是系统钥匙串**；和官方插件示例相同，
  不提供额外加密。退出会清除本机账号状态，并尽力注销服务端会话。勿分享插件数据目录。

## 音质设置

插件设置「音质」留空或填写 `auto` 时跟随宿主：标准 → `standard`、高 → `exhigh`、
无损 → `lossless`。也可填写以下任一值覆盖宿主的请求档位：

| 值         | 请求音质    |
| ---------- | ----------- |
| `standard` | 标准        |
| `higher`   | 较高        |
| `exhigh`   | 极高        |
| `lossless` | 无损 FLAC   |
| `hires`    | Hi-Res FLAC |

播放器使用实际返回格式、码率和增益。VIP、付费、地区及下架限制不会被绕过；试听片段不会作为完整歌曲播放。
宿主可能直接复用已缓存歌曲，插件无法清除宿主缓存；需要重新取流时可在宿主中手动清除缓存。

## 取流与风控

0.1.1 将取流请求的 User-Agent 与加密参数统一为 Windows 桌面客户端身份，继续使用已保存的设备标识。
同一会话、音频 ID 和实际请求音质的并发调用会合并；成功的地址短暂复用最多 10 秒，
且不超过服务端提供的有效期。音频文件缓存仍由宿主管理。

服务端返回 `-460`／`460` 风控或 `429` 限流时，取流进入 **60 秒冷却**。期间显示剩余等待时间，
不继续发起取流请求、不自动重试，也不将歌曲标成下架。冷却记录在重启后保留。
账号切换会清除地址缓存与待复用请求，避免复用旧账号权限；冷却仍保留，以减少对同一网络的重复请求。
这些措施减少重复请求及身份矛盾，不保证服务端风控一定解除。

## 开发与验证

使用 Node **26.13.0**、pnpm **12.18.0** 和 Vite+ **1.5.0**，版本及依赖锁定在仓库内。

```sh
vp install --frozen-lockfile
vp check
vp exec tsc --noEmit
vp test run
vp build
vp run package
vp run test:runtime
vp run test:live
```

构建会从 `src/` 生成根目录的单文件 `index.js`，不要手改该文件。安装包和干净安装目录位于 `dist/`，
同时生成 SHA-256；ZIP 不含开发依赖和缓存。发布前必须重新构建，并将生成的 `index.js` 随源码提交。

`test:runtime` 在 `.cache/` 中准备固定版本的临时 MyGo Music 检出，使用其真实
插件引擎和模拟网络验证；需要 Go 1.27.3 及宿主依赖下载。可设置
`MYGO_MUSIC_SOURCE=/path/to/local/mygo-music` 以复用本机 Git 源码。它不修改原宿主仓库。

`test:live` 仅匿名查询真实服务，不读取本机账号或发起写操作。网络、风控、地区和服务接口变化
可能使联网检查失败，结果与离线测试分开报告。真实扫码、付费音质和实际听感仍需本人账号验收。

Linux 使用约定的 `xjtuse-arch-dev` 增量同步流程测试，构建缓存不回传；测试证据见
[VALIDATION.md](VALIDATION.md)。
